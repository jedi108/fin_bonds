# Команда: `update-ratings`

## Описание
Обновляет отслеживаемые метрики облигаций: кредитный рейтинг, уровень листинга, уровень риска, купоны и т.д. (набор — `monitoring_adapters` в `config.yaml`). Результаты пишутся в `monitoring_checks` и `rating_history`, значимые изменения отправляются в Telegram.

Начиная с задачи 002.9 команда поддерживает **скоупы**: помимо портфеля можно дозаполнить рейтинги по бумагам каталога с «N/A» или прогнать весь каталог.

## Синтаксис
```bash
python3 main.py update-ratings [опции]
```

## Параметры

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `--isin` | string | — | Проверить одну бумагу **по каталогу** (позиция в портфеле не обязательна). Приоритетнее `--scope` (скоуп игнорируется, в логе пишется об этом). |
| `--scope` | choice | `portfolio` | Какие бумаги проверять (см. ниже). |
| `--limit` | int | — | Ограничить число бумаг. Применим только к `missing`/`catalog`; для `portfolio` игнорируется (warning в логе). |
| `--delay` | float | `0.5` | Пауза между бумагами в секундах для `missing`/`catalog`. |

## Скоупы

| Скоуп | Бумаги | Адаптеры |
|-------|--------|----------|
| `portfolio` (по умолчанию) | Бумаги портфеля (JOIN `portfolio_positions` × `bonds_catalog`) | Все из `monitoring_adapters` |
| `missing` | Живые бумаги каталога (`maturity_date >= CURRENT_DATE`), у которых последняя проверка `credit_rating` = `'N/A'` или проверки не было никогда | Только `credit_rating` |
| `catalog` | Все живые бумаги каталога, детерминированный порядок `ORDER BY isin` | Только `credit_rating` |

`--isin` проверяет любую бумагу каталога, независимо от наличия в портфеле, полным набором адаптеров.

⚠️ **Первый прогон `missing` ≈ полный каталог**: у большинства бумаг проверок `credit_rating` ещё не было. Дозируйте через `--limit` (рекомендуется порциями по 100–200) и не запускайте рядом с ночным окном (`run_update.sh`, блокировка `flock` защищает только сам скрипт — параллельный ручной запуск возможен).

## Источники рейтингов

Порядок опроса — `rating_providers` (factory), первый успешный выигрывает:

1. **MOEX ISS `/iss/cci/rating/...`** (002.9, Р10): `emitent_id` по ISIN (поиск ISS, фолбэк — `EMITTER_ID` из description) → карточка рейтингов выпуска. Возвращает рейтинги всех трёх агентств (АКРА/Эксперт РА/НКР); исторические записи со значением `Отозван` исключаются, берётся свежая по `rating_date`. Имя агентства попадает в лог, в БД не пишется (колонки `agency` в схеме нет).
2. **Smart-Lab** (fallback): HTML-скрейпинг `smart-lab.ru/q/bonds/<ISIN>/`, только код рейтинга, без агентства.

Код рейтинга нормализуется к шкале `rating_scale` из `config.yaml` (`normalize_rating_code`); в `rating_history` пишутся только коды из шкалы (балл — числом), `'N/A'` остаётся в `monitoring_checks` — это норма, не дефект. Запись идемпотентна за день (уникальный индекс `isin+rating_date+rating_code`, миграция 012): повторный прогон не создаёт дублей.

## Итоговая сводка

По завершении команда печатает одну строку (её читает скилл `finbonds-ratings`):

```
Итог: scope=missing; checked=50; rated=41; na=8; errors=1
```

## Уведомления

Telegram-отчёты о значимых изменениях отправляются только для скоупа `portfolio` и `--isin`. Скоупы `missing`/`catalog` пишут изменения в БД без уведомлений (anti-spam при массовых прогонах).

## Лимиты внешних источников

На каждую бумагу `missing`/`catalog` — 2–3 запроса (MOEX ISS: поиск + `/cci`; Smart-Lab: страница бумаги). Троттлинг между бумагами — `--delay` (по умолчанию 0.5 c); при массовых прогонах не уменьшайте его без необходимости — ISS недокументированный `/cci` и Smart-Lab (антибот) могут начать отдавать ошибки.

## Примеры

```bash
# Ночной прогон по портфелю (как в run_update.sh, шаг 4)
python3 main.py update-ratings

# Проверить одну бумагу каталога (в т.ч. вне портфеля)
python3 main.py update-ratings --isin RU000A1075J3

# Дозаполнить бумаги без рейтинга, порция 200
python3 main.py update-ratings --scope missing --limit 200

# Полный бэкфилл каталога (разовая операция, ~30-40 мин с дефолтным delay)
python3 main.py update-ratings --scope catalog
```
