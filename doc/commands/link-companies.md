# Команда: `link-companies`

## Описание

Привязка облигаций каталога к компаниям-эмитентам (юридическим лицам).
Создаёт справочник `companies` и связь «одна компания — много облигаций»
(`bonds_catalog.company_id` → `companies.id`).

Компания определяется нормализацией названия выпуска:
`«Газпром БО-22»` → `«Газпром»`, `«ЭР-Телеком Холдинг выпуск 3»` → `«ЭР-Телеком Холдинг»`,
`«Свердловская область 35008»` → регион `«Свердловская область»`, `«ОФЗ 26249»` →
суверенный `«Минфин России»`. Исключения правятся через `company_overrides` в `config.yaml`.

Кроме разового backfill, привязка новых облигаций выполняется автоматически
при `update-bonds`.

Схема рассчитана на развитие: на `companies.id` потом сошлются новости и теги
эмитентов — переделки схемы не потребуется.

## Синтаксис
```bash
python3 main.py link-companies [опции]
```

## Параметры

| Параметр | Тип | По умолчанию | Описание |
|----------|-----|--------------|----------|
| `--report` | flag | `false` | Только показать группировку, ничего не записывая |
| `--all` | flag | `false` | Перепривязать все облигации (по умолчанию — только без компании) |
| `--top` | int | `30` | Сколько крупнейших компаний показать в отчёте |

## Примеры

```bash
# Посмотреть, как сгруппируются облигации (без записи в БД)
python3 main.py link-companies --report

# Первичное наполнение / привязка новых облигаций
python3 main.py link-companies

# Перепривязать всё заново (например, после изменения overrides)
python3 main.py link-companies --all
```

## Схема данных

```sql
companies (id, name, full_name, inn, entity_type, created_at, updated_at)
-- entity_type: company | individual | region | sovereign
bonds_catalog.company_id -> companies.id   -- одна компания, много облигаций
```

- `inn` заполняется из API биржи / брокера по ISIN (ИНН физлиц-эмитентов не хранится). Переопределение `inn` через `company_overrides` в текущей версии не поддерживается при привязке к БД.
- Матчинг компаний регистронезависимый («Газпром Капитал» = «Газпром капитал»).

## Ручные переопределения (config.yaml)

Публичный пример фрагмента конфигурации доступен в корне проекта: [config.example.yaml](../../config.example.yaml).

> **Внимание:** `config.example.yaml` содержит **только** фрагмент конфигурации (`company_overrides`). Не копируйте его целиком поверх `config.yaml` (загрузчик читает только `config.yaml`), а добавьте нужную секцию в существующий `config.yaml`.

```yaml
company_overrides:
  # Вариант 1: Строка с каноническим именем (слияние вариантов в одно имя)
  "МФК Быстроденьги": "Быстроденьги"

  # Вариант 2: Словарь с указанием канонического имени и типа сущности
  "Газпром":
    name: "Газпром Капитал"
    entity_type: "company"
```

- **Ключ:** точное название выпуска либо нормализованное имя компании (точное название выпуска имеет наивысший приоритет).
- **Значение:** строка (каноническое имя) или словарь с полями `name` и `entity_type` (`company`, `individual`, `region`, `sovereign`).
- Ключи и строковые значения рекомендуется указывать в кавычках.

### Безопасный workflow применения переопределений

1. Добавьте фрагмент `company_overrides` в существующий `config.yaml`.
2. Проверьте результат группировки без записи в базу данных:
   ```bash
   python3 main.py link-companies --report
   ```
3. Осознанно примените изменения ко всему каталогу облигаций (флаг `--all` перепривязывает уже связанные облигации):
   ```bash
   python3 main.py link-companies --all
   ```
