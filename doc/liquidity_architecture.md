# Архитектура ликвидности в системе мониторинга портфеля

## Основные принципы

### Ликвидность как биржевое свойство

**Ключевой принцип:** Ликвидность является свойством ISIN на бирже, а не свойством брокера.

- **Стакан заявок** одинаков для всех брокеров, торгующих на одной бирже (MOEX)
- **Потери при выходе** из позиции одинаковы независимо от брокера
- **Анализ ликвидности** выполняется один раз для ISIN и применим ко всем брокерам

### Текущая реализация

#### Хранение данных
- **Таблица `monitoring_checks`**: `(isin, check_date, metric_name, metric_value)`
- **Метрика `liquidity_analyzer`**: коэффициент потерь в процентах
- **Таблица `portfolio_positions`**: поле `liquidity_loss_ratio` (может быть NULL)

#### Анализ ликвидности
- **Адаптер `LiquidityAnalyzerAdapter`**: получает стакан через TBank API
- **Расчёт потерь**: для целевой суммы (по умолчанию 60 000 ₽)
- **Глубина стакана**: 20 уровней (настраивается)

#### Использование в системе
- **Экспорт портфеля**: отображает потери при выходе для всех брокеров
- **Уведомления**: предупреждает о значимых изменениях ликвидности
- **Графики**: визуализация истории изменений ликвидности

## Ограничения текущей архитектуры

### Для бумаг Alor
- **Стакан не анализируется**: нет адаптера для Alor API
- **Отображение "N/A"**: вместо конкретного значения
- **Причина**: Alor API не предоставляет удобный доступ к стакану

### Для других брокеров
- **Единый источник**: только TBank API для анализа стакана
- **Ограничение**: если TBank недоступен, анализ не выполняется

## Рекомендации для разработчиков

### При добавлении новых брокеров
1. **Не создавайте отдельные адаптеры ликвидности** для каждого брокера
2. **Используйте единый анализ** через TBank API или MOEX API
3. **Сохраняйте результаты** в `monitoring_checks` по ISIN (без указания брокера)

### При изменении архитектуры
1. **Учтите зависимость** от схемы `monitoring_checks`
2. **Протестируйте все use cases**: `export-portfolio`, `update-ratings`, `analyze-liquidity`
3. **Обновите документацию** и комментарии в коде

### Альтернативные источники стакана
- **MOEX API**: прямой доступ к биржевым данным
- **Другие брокеры**: если предоставляют API для стакана
- **Агрегаторы**: сторонние сервисы с данными ликвидности

## Примеры использования

### Анализ ликвидности для конкретной бумаги
```bash
python3 main.py analyze-liquidity --isin RU000A10ASC6
```

### Обновление метрик ликвидности для всего портфеля
```bash
python3 main.py update-ratings
```

### Экспорт портфеля с данными ликвидности
```bash
python3 main.py export-portfolio --format console
```

## Технические детали

### Структура данных в БД
```sql
-- Результаты анализа ликвидности
SELECT isin, metric_value FROM monitoring_checks 
WHERE metric_name = 'liquidity_analyzer' 
ORDER BY check_date DESC;

-- Позиции портфеля с ликвидностью
SELECT isin, broker_name, liquidity_loss_ratio 
FROM portfolio_positions 
WHERE liquidity_loss_ratio IS NOT NULL;
```

### Конфигурация анализа
- `LIQUIDITY_TARGET_AMOUNT`: целевая сумма для расчёта (по умолчанию 60 000 ₽)
- `LIQUIDITY_DEPTH`: глубина стакана (по умолчанию 20 уровней)
- `LIQUIDITY_SIGNIFICANCE_THRESHOLD`: порог значимости изменений (по умолчанию 5%)
